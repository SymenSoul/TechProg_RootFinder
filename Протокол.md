# Протокол клиент–сервер

Клиент и сервер обмениваются текстовыми строками в кодировке UTF-8 по TCP, порт **33333**.
Одна команда — один ответ. Слова в команде разделяются пробелом.

| Команда                        | Ответ сервера |
|--------------------------------|---------------|
| `reg <login> <password>`       | `SUCCESS` — пользователь создан и сразу считается вошедшим; `ALREADY_EXISTS` — логин занят |
| `auth <login> <password>`      | `SUCCESS` или `FAILED` |
| `solve <funcId> <a> <b> <eps>` | `<бисекция>\|<Ньютон>` — два числа с 6 знаками после запятой; вместо числа может быть `FAILED` |
| любая другая строка            | `UNKNOWN COMMAND` |

Если у команды не хватает аргументов, сервер отвечает `FAILED`.

## Пример сеанса

```
→ reg student 123
← SUCCESS
→ auth student 123
← SUCCESS
→ solve 0 0 5 0.001
← 2.000122|2.000000
→ solve 0 -5 5 0.001
← FAILED|FAILED
→ hello
← UNKNOWN COMMAND
```

## Проверка вручную

Сервер можно проверить без клиента любым TCP-клиентом, например:

```bash
ncat 127.0.0.1 33333
```

Затем набирать команды построчно.

## Ограничения текущей версии

- Пароль и логин не могут содержать пробелы — строка делится по пробелам.
- Сервер выполняет `solve` даже без входа и хранит один «текущий логин» на всех клиентов.
